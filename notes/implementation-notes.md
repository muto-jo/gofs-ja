## 記録

### I-001 operator に事業主体・運行事業者・システム提供者を区別して書けない
- 対象: system_information.json / `name`, `short_name`, `operator`
- 実サービスの状況: 日本のデマンド交通では、事業主体（自治体）・運行事業者・運行システムの提供者が別であることが多い。例えば「のるーとふじ」は、事業主体が富士市、運行事業者が富士急静岡バス株式会社、運行システムがのるーと
- 疑問: `operator` には誰を書くべきか。また、3 者の関係を GOFS で表せるか
- 検討・解釈: `operator` は OPTIONAL の String が 1 つだけで、「Name of the on-demand service operator. The operator name MAY be the same as the system name.」とあるのみ。役割を区別する仕組みは無い。system は、`name` が乗客に表示する名前であることなどから、バックエンドのシステムではなく利用者から見た運行サービス全体と読める。そのため、のるーとのシステムを使って富士市で運行している「のるーとふじ」は、「のるーとふじ」として 1 つの system に定義してよい。GTFS の `attributions.txt` のように、組織ごとに producer・operator・authority の役割を付けられる仕組みを GOFS にも組み込んだほうがよい
- 結論: 現状の仕様では、のるーとふじの場合 `name`: のるーとふじ、`short_name`: 省略またはのるーとふじ、`operator`: 富士市 が妥当と訳者は考える。ただし `operator` を運行事業者（富士急静岡バス株式会社）とするのが妥当という意見も考えられる。役割の区別の仕組みは MobilityData への意見の候補とする
- 状態: 未決

### I-002 日本のタクシーの時間距離併用運賃を fares.json で正確に表せない
- 対象: fares.json / Fare オブジェクトの `start`, `end`、`kilometer`, `minute`, `active_minute`, `idle_minute`
- 実サービスの状況: 日本のタクシーは初乗距離が端数のある距離で決まっている（例: 金沢交通圏の初乗運賃は 1,220m まで 700 円）。また時間距離併用制運賃で、時速 10km 以下の低速走行・停止中は時間による加算に切り替わり、距離による加算は止まる（厳密には、時間を距離に換算して併算する）。金沢交通圏の初乗運賃・加算運賃の出典: GO 公式サイト「石川県のタクシー料金」https://go.goinc.jp/search/ishikawa （確認日 2026-11-10。初乗運賃 1,220m まで 700 円、以降 226m ごとに 100 円）。時間距離併用運賃の出典は未記入
- 疑問: fares.json でこの運賃を表せるか
- 検討・解釈: 次の 3 点で表しきれない
  1. `start` / `end` が Non-negative Integer なので、1.22km のような小数の距離を区間の境目にできない（T-023）
  2. `idle_minute` は「車両が停止している、または動いていない間」の 1 分あたりの価格とされ、低速走行が含まれない。日本の運賃に合わせるには、`idle_minute` の対象に低速走行（例: 時速 10km 以下）を加えてほしい
  3. fares.json はシステムで運賃を計算する方法を定めるもので、総額は `rider` の基本価格に `kilometer`・`minute`・`active_minute`・`idle_minute` の区分を加算したものとされる。日本の運賃は低速時に距離の加算が止まって時間に切り替わる（時間を距離に換算する）ため、各区分の単純な合算では正確に計算できない
- 結論: 未定。サンプルでの表し方（近似するか、表せない旨を記載するか）と、MobilityData に意見するかを検討する
- 状態: 未決

### I-003 迎車料金・予約料金・割増料金を定義できない
- 対象: fares.json
- 実サービスの状況: 日本のタクシーには、迎車料金、予約料金、深夜早朝などの割増料金がある。出典 URL・確認日は未記入
- 疑問: これらを fares.json で表せるか
- 検討・解釈: fares.json で定義できるのは `rider` の基本価格と、距離・時間（`kilometer`・`minute`・`active_minute`・`idle_minute`）による加算だけで、迎車・予約などの付加料金や、時間帯による割増を定義する仕組みが無い
- 結論: 未定。サンプルでの扱いと、MobilityData に意見するかを検討する
- 状態: 未決
